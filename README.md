# Акты выдачи оборудования

Локальное приложение для поиска конкретного экземпляра, ручного добавления оборудования и формирования акта Word. Интерфейс открывается на `http://127.0.0.1:8080/`. Данные хранятся в PostgreSQL; черновик акта живёт только в открытой странице. Для скачивания заполните номер, дату и получателя, добавьте устройства и нажмите «Сформировать Word».

## Первый запуск

Нужны Docker Desktop с работающим WSL 2 и Docker Compose. Команды ниже проверены в PowerShell из этой папки. Если Docker только что установлен, откройте новый терминал, чтобы обновился `PATH`.

1. Скопируйте `.env.example` в `.env` и задайте **свой уникальный** `DB_PASSWORD`. `.env` игнорируется Git. После первого запуска не меняйте пароль в `.env` без изменения пароля роли PostgreSQL: volume хранит прежние настройки БД.
2. Выполните:

```powershell
docker compose up -d db
docker compose --profile tools run --build --rm migrate
docker compose up -d --build web
docker compose ps
```

Адрес: `http://127.0.0.1:8080/`. Внешний порт PostgreSQL не опубликован. Порт веб-сервиса опубликован только на `127.0.0.1`. Схема меняется только отдельной командой `migrate`; запуск `web` миграции не выполняет. Применённые SQL-файлы и их SHA-256 записываются в `schema_migrations`. Изменения схемы добавляйте новым файлом миграции; существующие применённые файлы не редактируйте.

Остановить без удаления данных:

```powershell
docker compose down
```

Именованный volume `equipment-act_postgres_data` при такой остановке остаётся. Обычная остановка не должна использовать `down -v`.

## Работа с приложением

«Новое оборудование» создаёт одну запись в базе. После сохранения карточка выбирается, но ещё не попадает в акт. Поиск работает по типу, модели, инвентарному и серийному номерам; нажмите на нужный экземпляр, затем «Добавить в акт». «Убрать» меняет только список акта. Получатель отличается от текущего ответственного; составление акта не меняет учётную запись и не проводит передачу в 1С. Суммы и детали списка сервер заново берёт из базы. Для очистки черновика обновите страницу.

Инвентарный номер сравнивается без учёта регистра и пробелов по краям. Начальные нули, дефисы и внутренние символы сохраняются. Серийный номер не считается глобально уникальным. Денежные значения вводятся в рублях с точкой и двумя знаками; внутри хранятся целые копейки. «Без НДС» и «НДС 0%» — разные режимы.

## Импорт CSV

Контракт: UTF-8 с необязательным BOM; разделитель `;`; заголовок обязателен и должен совпадать с [примером](examples/assets-demo.csv). Даты — `YYYY-MM-DD`, суммы — `1234.56`. Стоимость и НДС берутся из выгрузки без пересчёта. Один инвентарный номер — один физический экземпляр в одном контуре учёта. Если в реальной выгрузке номер повторяется между организациями, сначала нужно согласовать другой ключ; такие записи нельзя объединять автоматически.

Поместите согласованный файл в папку `input/` (она игнорируется Git). Проверка по умолчанию ничего не записывает:

```powershell
docker compose --profile tools run --rm importer --file /input/assets.csv
docker compose --profile tools run --rm importer --file /input/assets.csv --apply
```

Вторая команда добавляет новые записи одной транзакцией. Идентичные строки уже загруженного файла пропускаются. Совпавший номер с другими реквизитами даёт конфликт; ошибка в любой строке или конфликт отменяют запись всего файла. Ошибки указывают номер CSV-записи и поле. Исправление существующих записей через импорт не выполняется. Максимум: 10 МиБ и 10 000 записей в одном файле.

Обезличенный пример для проверки: скопировать `examples/assets-demo.csv` в `input/assets.csv`, затем выполнить две команды выше. Пример не загружается автоматически.

## Резервная копия и восстановление

Перед миграцией рабочей базы сделайте резервную копию и проверьте восстановление на отдельной базе. Следующие команды проверены для имён БД и роли из `.env.example`; при изменённых именах замените их. Выберите новое имя файла, чтобы не перезаписать предыдущую копию.

```powershell
New-Item -ItemType Directory -Force backups
docker compose exec -T db pg_dump -U equipment_act -d equipment_act -Fc -f /tmp/equipment-act-backup.dump
docker cp equipment-act-db-1:/tmp/equipment-act-backup.dump .\backups\equipment-act-YYYYMMDD.dump
```

Проверка восстановления **в новой отдельной БД**:

```powershell
docker compose exec -T db createdb -U equipment_act equipment_act_restore_test
docker cp .\backups\equipment-act-YYYYMMDD.dump equipment-act-db-1:/tmp/equipment-act-restore-test.dump
docker compose exec -T db pg_restore -U equipment_act -d equipment_act_restore_test --no-owner --no-privileges /tmp/equipment-act-restore-test.dump
docker compose exec -T db psql -U equipment_act -d equipment_act_restore_test -Atc "select count(*) from assets"
```

Выберите другое имя тестовой БД, если `equipment_act_restore_test` уже существует. Эти команды не перезаписывают рабочую БД. Каталог `backups/` игнорируется Git.

## Разработка и проверки

Стек: Go 1.27.1 (`net/http`, `html/template`), `pgx/v5` 5.11.0, PostgreSQL 18.6 с `pg_trgm` и GIN-индексами, Docker Compose. Версии зафиксированы в `go.mod`, `Dockerfile` и `compose.yaml`. `github.com/lukasjarosch/go-docx` v0.5.0 заполняет рабочую копию реального шаблона; обработчик `internal/docgen` повторяет только её строку оборудования.

```powershell
go test ./cmd/... ./internal/... ./web/...
docker compose --profile test run --build --rm test
```

Вторая команда выполняет также интеграционные тесты на PostgreSQL во временных схемах. Тестовая роль должна иметь право создать схему и установить `pg_trgm`; при настройках из `.env.example` это выполнено.

Фактические проверки записаны в [VERIFICATION.md](VERIFICATION.md). Назначение маркеров, источники значений, ручные реквизиты и правило повторения строки определены в [TEMPLATE_CONTRACT.md](TEMPLATE_CONTRACT.md).

## Формирование Word

Исходный `акт_шаблон.docx` сохранён в корне. Рабочая копия `templates/act/акт_рабочий.docx` встроена в сервер. После изменения шаблона выполните `docker compose up -d --build web`.

Одна строка — один экземпляр, количество всегда 1; максимум 100 устройств. Сервер заново читает записи по ID, сверяет версии и рассчитывает стоимость. Если запись изменилась, скачивание отменяется, интерфейс обновляет данные и показывает изменения; после проверки нажмите кнопку повторно. Цена, НДС и ответственный из браузера не принимаются.

DOCX полностью формируется и проверяется в памяти до отправки. При ошибке сайт показывает сообщение. Каждый запрос независим; временные DOCX на сервере не сохраняются. Формирование не изменяет текущего ответственного.

Получатель вставляется в вводный абзац перед паспортными реквизитами, номер — в заголовок. Паспортные данные, реквизиты работодателя, должности, состояние и подписи заполняются вручную по исходной форме; вопросы к их автоматизации перечислены в контракте.

Проверки именно этапа C и повторное создание вымышленных образцов:

```powershell
go run ./cmd/docx-samples
go test ./internal/docgen ./internal/httpapp
docker compose --profile test run --build --rm test go test -race ./internal/docgen ./internal/httpapp
```

Образцы на 1, 3 и 18 устройств появляются в `output/stage-c/`. Проверка HTTP с PostgreSQL без `TEST_DATABASE_URL` пропускается; команда Docker задаёт подключение и использует отдельную временную схему. Примеры не загружают данные в рабочую БД.
