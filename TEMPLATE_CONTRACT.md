# Контракт шаблона акта ТМЦ

Исходник: `акт_шаблон.docx` в корне проекта. Рабочая копия: `templates/act/акт_рабочий.docx`. Оригинал не изменяется. Рабочий шаблон встраивается в сервер при сборке; после его изменения сервер нужно пересобрать. Генератор: `internal/docgen`, библиотека `go-docx` v0.5.0.

## Поля и источники

| Маркер | Место и назначение | Источник | Обязательность |
|---|---|---|---|
| DATE | Строка рядом с «г. Москва»: дата акта | Поле «Дата акта», YYYY-MM-DD → DD.MM.YYYY | Да |
| ACT_NUMBER | Добавлен в заголовок «Акт № …» | «Номер акта», до 100 символов | Да |
| RECIPIENT | Добавлен вместо первого подчёркнутого пробела перед «паспорт»: ФИО работника | «Кому передаём», до 500 символов | Да |
| ROW_NO | Столбец «№ п/п» | Позиция в списке на сайте, начиная с 1 | Автоматически |
| NAME | Столбец «Наименование материальных ценностей», строка оборудования | Тип + модель из БД | Да |
| INV | Столбец «Инв. №» | Инвентарный номер из БД | Да |
| SN | Столбец «Серийный номер» | Серийный номер из БД; при отсутствии — тире | Нет |
| COUNT | Столбец «Кол-во» | Всегда 1: одна строка — один физический экземпляр | Автоматически |
| PRICE | Столбец «Стоимость, руб.» | Цена экземпляра и реквизиты НДС из БД, полная строка money.Cost | Да |
| COMMON_PRICE | Последняя строка таблицы «Итоговая стоимость…» | Сумма цен в целых копейках; отдельно суммы НДС по ставкам и стоимость позиций без НДС | Автоматически |

NAME обозначает оборудование по расположению под заголовком таблицы. Получатель — отдельное поле RECIPIENT. Колонка единиц измерения сохраняет исходное «шт.».

## Повторение строки

Только в основной таблице повторяется одна строка с ROW_NO, NAME, INV, SN, COUNT, PRICE. Сохраняются XML-теги, свойства ячеек, границы и оформление. Обработчик Go объединяет фрагменты известных маркеров внутри абзаца, клонирует строку и присваивает маркеры NAME_1, NAME_2 и т. д. Затем значения вставляет go-docx. Остальные части DOCX не редактируются во время формирования. Допускается 1–100 различных ID, порядок точно соответствует списку запроса. Заголовок повторяется на следующих страницах, итог следует за последней позицией.

Каждый запрос создаёт самостоятельный документ в памяти. Использование go-docx сериализовано из-за общих счётчиков библиотеки; содержимое запросов не разделяется. Сервер повторно читает записи из PostgreSQL, проверяет ID и версии выбранных данных. При изменении данных возвращается 409; пользователь видит обновлённые сведения и повторяет формирование. Цены из браузера не принимаются. Текущий ответственный и записи БД при формировании не меняются.

## Изменения рабочей копии

- Двойные скобки заменены одинарными, включая разбитый на два фрагмента DATE.
- Убрана точная высота: исходная строка оборудования 1 см, итог 0,6 см и заголовок 1,5 см обрезали переполняющий текст. Строки растут по содержимому.
- Исходные 20,5 см ширины таблицы уменьшены до доступных 17,75 см. Согласованы сетка, ширины ячеек и объединённая ячейка итога.
- Проверены переносы: noWrap отсутствовал в исходных ячейках, межстрочный интервал был автоматическим. Основная причина обрезания — точная высота, дополнительная проблема — ширина таблицы.
- Размер основного текста 12 пт и шрифт исходника сохранены. В узких столбцах уменьшены боковые отступы; подписи заголовков не сокращены.
- Сохранены колонтитул, подписи и текст акта; пояснения к состоянию и блок подписей удерживаются вместе при переходе страницы.

## Оставшиеся содержательные вопросы

В исходнике перед «с одной стороны» нет реквизитов работодателя. В интерфейсе также нет работодателя, паспортных данных, должности, состояния и замечаний. Эти сведения не выдумываются: исходные места ручного заполнения сохранены. Для полного автоматического заполнения нужно определить источник реквизитов работодателя и решить, требуются ли паспортные поля. ФИО получателя заполняется в вводном абзаце; должность, ФИО и подпись в нижней подписной строке пока остаются для ручного оформления.

Это не мешает техническому формированию акта по текущему интерфейсу. Готовый файл требует проверки и заполнения оставшихся реквизитов перед подписанием.

## Пример и проверка

Обезличенные входные данные: `templates/act/example-input.json`. Воспроизводимые примеры: `go run ./cmd/docx-samples` (записывает `output/stage-c/act-01.docx`, `act-03.docx`, `act-18.docx`). При изменении шаблона обязательны структурная проверка и просмотр всех страниц через Microsoft Word.
